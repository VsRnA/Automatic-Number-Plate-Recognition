# Тестирование функционала Camera + Workers

## Предварительные требования

1. Применить миграцию `20260702130000-createCamerasTable.sql`
2. Установить зависимость `httpx` в Python service
3. Запустить Go backend и Python service-recognition

---

## Фаза 1: Camera CRUD (Go Backend)

### Создание камеры
- Создать камеру с валидными данными
- Создать камеру с `isActive: false`
- Создать камеру с `isActive: true`
- Попытка создать камеру с дублирующимся именем (ожидается ошибка 409)
- Попытка создать камеру без обязательных полей (ожидается ошибка 400)
- Попытка создать камеру с невалидным URL (ожидается ошибка 400)

### Получение камеры
- Получить камеру по существующему ID
- Попытка получить камеру по несуществующему ID (ожидается ошибка 404)
- Попытка получить камеру с невалидным UUID (ожидается ошибка 400)

### Список камер
- Получить список всех камер
- Получить список с пагинацией (limit, offset)
- Получить список только активных камер (`isActive=true`)

### Обновление камеры
- Обновить имя камеры
- Обновить RTSP URL камеры
- Изменить `isActive` с false на true
- Изменить `isActive` с true на false
- Попытка обновить несуществующую камеру (ожидается ошибка 404)

### Удаление камеры
- Удалить неактивную камеру
- Удалить активную камеру (должен остановить воркер)
- Попытка удалить несуществующую камеру (ожидается ошибка 404)

## Фаза 2: Worker Management (gRPC Go → Python)

### StartWorker
- Создать камеру с `isActive: true` → проверить, что воркер запустился в Python
- Обновить камеру `isActive: false → true` → проверить запуск воркера
- Попытка запустить воркер для уже запущенной камеры

### StopWorker
- Обновить камеру `isActive: true → false` → проверить остановку воркера
- Удалить активную камеру → проверить остановку воркера
- Попытка остановить несуществующий воркер

### GetWorkerStatus
- Проверить статус запущенного воркера (status: "running")
- Проверить статус остановленного воркера (status: "stopped")
- Проверить статус несуществующего воркера

---

## Фаза 3: Recovery (Python → Go)

### Восстановление при старте Python
1. Создать несколько камер с `isActive: true`
2. Перезапустить Python service
3. Проверить логи: "Recovery complete: started N workers"
4. Проверить, что все активные камеры имеют запущенные воркеры

### Recovery при недоступном Go backend
1. Остановить Go backend
2. Запустить Python service
3. Проверить, что сервис запустился без ошибок (graceful degradation)
4. Проверить логи об ошибке подключения к backend

---

## Фаза 4: Интеграционные сценарии

### Полный цикл жизни камеры
1. Создать камеру (неактивную)
2. Активировать камеру
3. Проверить статус воркера
4. Деактивировать камеру
5. Проверить остановку воркера
6. Удалить камеру

### Несколько камер одновременно
1. Создать 3 камеры с `isActive: true`
2. Проверить, что все 3 воркера запущены
3. Деактивировать одну камеру
4. Проверить, что остальные 2 воркера работают
5. Перезапустить Python service
6. Проверить recovery для 2 активных камер

### Обработка ошибок gRPC
1. Остановить Python service
2. Попытаться создать камеру с `isActive: true`
3. Проверить, что камера создалась в БД
4. Проверить warning в логах Go о недоступности Python
5. Запустить Python service
6. Проверить recovery

---

## Проверка логов

### Go Backend
- Лог при запуске воркера: "Started worker for camera..."
- Лог при остановке воркера: "Stopped worker for camera..."
- Warning при недоступности Python service

### Python Service
- Лог при старте: "Starting recognition service on port..."
- Лог recovery: "Recovery complete: started N workers"
- Лог запуска воркера: "Started worker for camera..."
- Лог остановки воркера: "Stopped worker for camera..."
