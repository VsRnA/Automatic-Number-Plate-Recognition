1. Не нравиться валидация параметров переданных в request не посредственно в хенделерах, как будто можно попробовать добавить какие нибудь .yml файлы для валидации ожидаемых параметров и генерировать swagger из .yml документации. И тогда по идее не придется делать интерфейсы request для handler`s в моделях

2. Функции в репозиториях не совсем универсальны, как будто вот такой подход
```
	err := r.db.Where("guid = ?", id).First(&camera).Error
```

не дает возможности быстро добавить новые параметры в запрос, хотелось бы быстрее и легче добавлять новые параметры

3. Service - это вынесение общего функционала, а не логики handler`s. То есть в service лучше выносить функции по типы JWT аутентификации (генерации и проверки токенов), сейчас же у нас там логика хендлеров что по идее не очень корректно.


4. Поменяем таблицу в бд **Cameras:** и соотвественно все взаимодействия с ней

| Переменная | Тип | Описание |
|---|---|---|
| guid | UUID | Уникальный идентификатор |
| name | string | Название камеры |
| stream | string | RTSP URL (SD, для превью) |
| streamHd | string | RTSP URL (HD, для распознавания) |
| login | string (null) | Логин для подключения |
| password | string (null) | Пароль (зашифрованный) |
| accessPointId | number (FK) | ID точки доступа |
| isEnabled | boolean | Активна ли камера |
| metadata | JSONB (null) | Доп. параметры камеры |
| createdAt | timestamp | Дата создания |
| updatedAt | timestamp | Дата обновления |
| deletedAt | timestamp (null) | Дата soft-удаления |
